# sanitize 判定基準 — 公開リポへの作業リポ固有情報の漏洩監査

PUBLIC リポ（crgstar/dotfiles）に載る内容（コミット差分・提案の変更内容・コミットメッセージ）を
検査するときの判定基準。sanitize-auditor サブエージェントと reflect の headless 監査プロンプトが
このファイルを唯一の正として読む。

## 監査観点

以下のいずれかが含まれていたら「漏洩あり」:

- 絶対パス (`/Users/.../...`) が残っていないか
- 作業リポ名・組織名・社内サービス名・他人の名前が混ざっていないか
- API キー・トークン・メール・IP・社内ホスト名・`.env` 値が混ざっていないか
- 作業リポ固有のコード識別子 (型名・関数名・ドメイン用語) が残っていないか

## 迷う語の扱い

迷う語は、まず dotfiles リポの追跡済みファイルに同語が既出か Grep で確認する。既出なら
既公開情報なので漏洩に数えない (一般語まで漏洩判定すると誤発報する)。
確認してもなお迷うなら「漏洩あり」に倒す — 漏洩は 1 度起こすと取り返しが付かないため、
false positive で止める方が常に正しい。

## 例外

dotfiles 管理スキル名 (`create-pr`, `sentinel` 等) は指摘・提案の対象そのものなので残してよい。
ワークフロー的な抽象記述・一般的な技術用語も漏洩に数えない。
