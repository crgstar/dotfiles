  Claude Code のプロジェクト別永続メモリ（memory/ 配下の *.md と MEMORY.md 索引）を書く・
  更新・リネームするときの基準。メモリへの保存・追記・書き直し・「これを覚えて」への対応で
  常に適用する。メモリ全体を一括で棚卸し・削減する工程は tidy-memory の領分で対象外だが、
  そこでの判定・書式は本スキルが正本。メモリ以外のドキュメント執筆は対象外。

メモリの価値は「次に同じ状況が来たとき行動が変わるか」だけで測る。書く判定も、既存メモリを残す / 消す判定も同じ基準で測る。

種別（user / feedback / project / reference）の定義と frontmatter・索引の基本形は、システムプロンプトのメモリ指示が正本。既存メモリは必ずディスクから読む。セッションに注入されている MEMORY.md はセッション開始時のスナップショットで、ディスクと乖離しうる。

## 何を書くか・何を残すか

- feedback 系の生存条件は「**状況トリガー + 行動を索引フックの 1 行に要約できて、CLAUDE.md・CLAUDE.local.md・スキル本文・リポジトリの文書から導出できない**」こと。導出できる一般規律（裏取りしろ・探してから無いと言え・読み手に合わせろ系）は、メモリに置いても再発を防げない
  - 文面が注入指示と同じでも、注入指示の届かない実行主体（委譲先エージェント等）への具体的な行動になっているものは書ける。出力先の場面（「PR 返信では」等）は実行主体ではない — 場面を付ければ何でも通る抜け道になるため
  - 導出可否の確認は、該当しそうな文書・スキル 1〜2 本を grep する程度でよい。単発の保存では確信が持てなければ書いて通してよい（過剰分は次回の tidy-memory が落とす）
- スキル本文に規定を内在化できるなら、メモリでなくスキルを直す。スキルは該当作業で必ず読まれるが、メモリは想起されないことがある

## どこに書くか

- 新規ファイルより既存ファイルへの追記を先に検討する。索引の 1 行追加は他の全行の想起率を下げるので、ファイルを増やすこと自体にコストがある。重複はファイル名・索引だけでなく**本文を grep して**探す（個々のルールは束ねられたファイルの本文に埋まっている）
- ファイル分割は場面（ツール・作業種別・機能群）起点で決め、種別を問わず 1 場面 1 ファイルに束ねる。想起は場面単位で起きるので、種別より場面で束ねたほうが一緒に読まれる。目安は 1 ファイル 40 行・ルール 6〜7 個まで（これを超えると想起されても通読されず、埋まったルールが死ぬ）
  - 読み流しはファイルを細かく保つことでなく、各ルールを自己完結の箇条書き 1〜3 行に圧縮することで防ぐ（本文は想起されたときに読む詳細のため）
- 正本が docs にある実装済み機能の教訓は、機能ごとに独立ファイルにせず機能群の場面で束ねる。単独ファイルで残す理由になるのは「消えたら作業を再開・再現できない外部実体へのポインタ」（未マージブランチ・worktree・tag・未確定の判断待ち）だけ
- 「知りたいこと → 開く先」の写像は、対象プロジェクト初見の Claude にとって開く先が非自明なものだけ対応表ファイルに足す（無ければ作る）
- 同じ事実を 2 ファイルに書かない。片方だけ更新されて食い違うため。置き先が割れたら片方に書き、他方からは `[[name]]` でリンクする

## 陳腐化しない書き方

書く時点で「1 か月後に嘘になる記述か」を確かめる。事後の棚卸しで直すより書く時点の予防が安い。

- 状態（未コミット・未マージ・成績・件数・進捗）でなく、機序（なぜそうなるか・何が変わらないか）と正本へのポインタを書く。状態をどうしても書くなら「〜時点」を付ける。ユーザが状態値の保存を明示したときも、基準を理由に黙って捨てず「〜時点」付きで保存し、正本ファイルがあるならポインタ化を提案する
- 行番号は書かない（ファイル名まで）。個別事例の列挙（対象番号・実行結果の一覧）は原則に一般化して書く
- 行動を変える力は索引行と frontmatter の description にある。そこに「状況トリガー → 行動」を書く。ただし網羅列挙せず代表トリガーに絞る（伸ばすほど読まれなくなる）

## 書式・リネーム

システムプロンプトの基本形への追加規定のみ:

- `name` はファイル名と一致させる。ツールが付与する frontmatter キー（`modified` 等）は自分で書かない・触らない
- 失敗事例を物語にしない。実事例が状況の認識を助けるときだけ、ルール末尾にインラインで「由来: 〜」最大 1 行
- リネームの手順:
  1. 旧ファイル名の stem で参照元を grep する。範囲はメモリディレクトリ全体（他メモリの `[[リンク]]`・MEMORY.md 索引）と作業リポジトリ（CLAUDE.md / CLAUDE.local.md 等）
  2. 自分で編集できない参照元（送信済みの PR 本文等）が見つかったら、ここで中止して名前を維持する。直せないリンク切れが残るため
  3. mv でリネームし、frontmatter の `name` を同期し、1 で見つけた参照元を同時に更新する
