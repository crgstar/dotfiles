# 読者と目的を先に決める

誰が読み、読者がそこから何を持ち帰るかを、書き始める前にユーザに 1 行で示し、合意を取る。
読者と目的は文書に書かない。節も文も、読者と目的に照らして要るものだけを書き、要らないものは作らない。順序、粒度、言葉もそれに照らして決める。

# 省略も言い換えもしない

主語、目的語、それぞれの語が何を指すかを、読者に文脈から補わせずに書く。
画面やコードに出てくる名前は、縮めたり言い換えたりせずそのまま書く。

# 上から順に読んで意味が通るように書く

用語や呼び名は、初めて使う箇所かそれより前で定義する。「案 A」のような呼び名を、定義より前に使わない。

# 最新の確定結果だけを書く

検討の途中経過、没案、草案、経過報告は書かない。「最初は X を検討した」のような、書き手の調査の過程も書かない。

# 議論していない決定を書かない

ユーザと合意していない技術選択は、書く前に「ここまで含めますか?」と聞く。権限、上限値、タイムアウト、実装手段、レイヤー配置、テスト方針などがこれにあたる。

# 同じことは 1 か所にだけ書く

リンク先、画像、文書内のほかの箇所を見れば分かることは書かない。念押しも書かない。概要には、後の節で書く細部を入れない。

# 理由を書くなら、決定のすぐ横に 1 文で書く

理由には、ほかの形にすると何が起きるかを書く。決定を言い換えただけの文は理由にならない。

# 図や表は、何を表すかを決めてから使う

図や表を使う前に、それで何を表すかを決める。表なら、表全体と行と列のそれぞれが何を表すかを決め、何を表すか決められない行や列は作らない。図なら、箱や矢印のそれぞれが何を表すかを決める。
