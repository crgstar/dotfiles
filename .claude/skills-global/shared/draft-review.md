# PR に出す文章の下書きと推敲

返信・指摘コメントなど PR に出す文章を、下書きからユーザーの合意まで進める共通手順。何を基準に推敲するかは呼び出し元のスキルが渡す。

1. 下書きはリポジトリ外のファイルに書く。版ごとに別ファイルにし、上書きしない。1 件ごとに投稿先（ファイル:行と対象コミット、または返信先のコメント）を見出しで書き、見出しは投稿する本文に含めない。
2. 推敲をサブエージェントに任せる。プロンプトには次を書く。
   - 下書きのパスと、書き直しを書き出す新しいファイルのパス
   - 呼び出し元の基準（参照パスではなく本文を含める）
   - 基準に沿って短縮し、引用（ファイル:行、対象コミット）を現物と照合し、Skill ツールで `unslop` を起動してかけ、`yomiyasu` が Skill の一覧にあれば同じく起動して続けてかける。英語の文章なら両スキルは起動せず、`~/.claude/skills/unslop/reference-en.md` を読んでかける。yomiyasu が別のファイルに書き出したら、その最終稿のパスを返す
   - 固定文字列は変えない: コミットハッシュの ` (abc1234)` の形（直前の半角スペースも消さない）、署名行（yomiyasu が絵文字を警告しても残す）、重要度タグ、suggestion ブロック、投稿先を示す見出し
   - 投稿しない。下書きとリポジトリは書き換えない
3. 下書きと最終稿の差分を見て、変わった事実・引用・削られた条件・言い切りの強さを自分で確かめてから採る。確かめずに取り込むと、サブエージェントの誤りを自分の主張として公開することになる。
4. ユーザーに見せる。置き場所と投稿先を書き、本文は初回は全文、2 回目以降は前回見せた版との差分を出す。
   - 短ければチャットに貼る。差分は句読点の単位で取る（行単位だと段落ごと置き換わって見える）:
     `git diff --no-index --word-diff=plain --word-diff-regex='[^[:space:]、。]+[、。]?' <前の版> <今の版>`
   - 長ければ `code <ファイル>` / `code --diff <前の版> <今の版>` で開く。`code` が無ければチャットに貼る
5. 合意が取れた版を投稿する。
